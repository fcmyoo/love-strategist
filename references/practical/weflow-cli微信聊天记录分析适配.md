# weflow-cli 微信聊天记录分析适配

## 定位

weflow-cli 负责**在用户自己的本机**读取、检索、导出微信聊天记录，并返回带结构化元数据的证据；恋爱小助手负责情绪承接、事实／推测拆分、关系判断与行动建议。

与旧版 ChatLab 适配的关键差异（先想清楚这点再往下读）：

| 维度 | ChatLab（原） | weflow-cli（本机工具） |
|---|---|---|
| 数据来源 | 用户已导出的文件，需再导入 | 直接读本机微信数据目录 |
| 证据编号 | `[#1021]` 形式的会话内编号 | 每条消息自带时间戳、发送方身份与本地序号 |
| 关系信号 | 靠查询命令手工拼 | 内置主动频率、回复间隔、消费/转账等统计能力 |
| 边界 | 不读应用数据库 | 只读本地数据，不联网、不发送、需用户自己拥有该设备与账号 |

weflow-cli 的能力契约可能随版本变化，运行前以 `weflow-cli --help` 和 `weflow-cli capabilities` 为准。源码：<https://github.com/fcmyoo/weflow-cli>

## 边界（不可越线）

- **只读**：只查询、导出、分析，绝不修改微信数据库、绝不动消息。
- **发送属于另一件事**：`weflow-cli send` 与 `draft --send` 会真的把消息发出去。除非用户明确要求代发，否则只用 `draft` 产出文本给用户自己发。
- **不越权解密**：不指导用户绕过设备权限、不索取他人数据、不把导出内容上传到外部服务。
- **未初始化就停下**：`weflow-cli init` 需要用户退出微信并在本机手动执行；工具未就绪时只给命令，不代跑。
- **隐私最小化**：导出文件、证据包、原始聊天不进入长期记忆，也不外传。

## 先锁定说话人

分析前建立并显示固定映射，例如"用户＝wxid_leewin…（右侧），对象A＝wxid_ot2pzyt…（左侧）"。没有确认前不解释关系：

- weflow-cli 返回的发送方身份（wxid／昵称／备注）优先于**任何**位置、颜色、语气或性别推断。左右与颜色随应用、导出方式和截图者变化。
- 昵称搜索有坑：**匹配只搜 wxid／昵称／备注，不搜"微信号"别名**。对方微信号与昵称不一致时，用 `contacts -k <昵称片段>` 先拿到 wxid，再进入 `messages`。
- 多候选同名时加 `--non-interactive`，让工具直接报"匹配不唯一"，而不是猜一个。

## 定位对象

```bash
weflow-cli contacts -k 晶晶 --json      # 按昵称/备注/微信号片段找 wxid
weflow-cli sessions -k <关键词> --json   # 从最近会话列表定位
```

拿到 wxid 后再进入消息查询。

## 读取消息

先看会话概览，再按时间窗口取具体片段：

```bash
weflow-cli messages <talker> -n 50 --json
weflow-cli messages <talker> --from 2026-10-19 --to 2026-10-21 --json
weflow-cli messages <talker> -n 200 -o 200 --json    # 翻页：offset
```

`-n/--limit` 是条数，`-o/--offset` 是偏移量，`-s/-e` 是时间戳上下界，`--json` 输出机器可读结果。**先窄后宽**：先用小窗口定位事件，再扩到全量。

## 全量导出（做整体关系分析时）

```bash
weflow-cli export <talker> json -o <绝对路径> --media      # JSON + 图片/文档落盘
weflow-cli export <talker> md   -o <绝对路径>              # 分卷 Markdown，人读友好
weflow-cli export <talker> json -o <路径> --from <起> --to <止>
```

- `--contract weflow-v1` 可输出带完整元数据的规范化契约（更适合程序化分析）。
- `--media` 会把图片文档抽到 `<输出>/<会话>_assets` 并在导出物里给出相对路径。
- Markdown 导出里**表情消息显示为"（空）"**，需要真实表情文本时去读 JSON（`localType=1`，`content` 内含 `[破涕为笑]` 等方括号标记）。
- 文本截断或内容缺失时，用 `weflow-cli sync` 查看重叠窗口与覆盖报告，确认是否为读取窗口问题而非记录缺失。

## 证据包（需要可复核引用时）

```bash
weflow-cli evidence <talker> -o <目录> --case "<争议说明>" --json
```

输出原始消息、哈希与保全说明，适合需要固定引用、防止事后争议的场景。引用时保留时间戳＋发送方＋消息原文三元组，不引用脱离上下文的单句。

## 关系信号与趋势

- `weflow-cli report`（聊天月报）、`weflow-cli chat-stats`（支付＋转账消费报告）、`weflow-cli annual-report`（年度数字生活报告）、`weflow-cli ledger`（红包转账流水）都能直接给出**已聚合的行为数据**：主动频率、回应节奏、金钱往来。优先展示这些可解释指标，而不是凭印象判断"他忽冷忽热"。
- `weflow-cli search <query> --line chat` 在全部聊天记录里做语义检索（"他提过几次加班""哪次吵架后主动找我"）。
- `weflow-cli awaiting` 判断**谁在等我回话**；`weflow-cli draft <talker>` 先判意图与风险再起草候选回复（默认只出文本，不发送）。这两条与 `references/practical/实战话术编排器：从一句回复到后续分支.md` 配合使用。
- 涉及争议线索（转账、承诺、威胁）时用 `weflow-cli evidence-review`，它只整理线索、**不给法律结论**。

任何模型评分、K 线、指标都只是主观投影，不能据此判断爱意、忠诚或分手概率，也不能写进长期记忆的稳定档案。

## 回答与记忆边界

回答开头说明实际查询的会话和时间范围。分开写：

1. 可观察事实：主动次数、兑现、时间间隔、明确原话（带时间戳）。
2. 合理解释：可能的关系含义和其他解释。
3. 关键未知：线下互动、没有说出口的意图、应用外事件。
4. 建议：低成本验证动作、观察窗口和停止条件。

原始聊天、长摘要和统计表不进入长期记忆。首次同意后，也只允许把关键事件的简短摘要、日期和证据编号写入 `event`；由 weflow-cli 统计或模型得出的性格与意图只能写入 `hypothesis`，不能升级为对象事实。

## 安全场景优先级

若对象涉及家暴、跟踪、定位监控或其他人身安全风险：

- 先确认安全，再谈关系策略；必要时直接给 12338／110／人身安全保护令／12356 心理援助等资源。
- 关系策略分析降级为次要，且**不输出任何可能暴露用户位置、行程或意图的话术**。
